## 1. 从 PDF 导入教材（课文）

**状态**：已设计 · **待开发** · 阻塞在一项前置验证（见「未知数」）

### 需求边界（已确认）

- **只导入课文** —— 提取「单元 / 标题 / 正文」，即现有的
  `{unit, title, text}` 结构，进语料库，供「整本书阅读」等阅读题型使用。
  **不含**生字表 / 词语表 / 习题（那需要另建「用户扩展教材数据层」，
  因为它要落到教材数据本身而不只是语料库）。
- **目标 PDF：出版社电子版**（含文本层），不是手机翻拍的扫描件。

### 现状盘点（一半能力项目里已经具备）

| 能力 | 位置 | 状态 |
|---|---|---|
| 图片 → 多模态 AI → 结构化课文 | `chinese_panel._importCorpusFromImage()` | 已实现（拍照导入走的正是这条） |
| 多模态请求通道 | `ai_client.chat(imageBase64:)` → OpenAI 兼容 `image_url` | 已实现 |
| 语料模型（**`origin` 本来就留了扩展位**） | `Corpus`：`bundled` / `imported-json` / `photo` / `ai` | 已实现 |
| 文件选择 | `file_picker`（目前仅 `allowedExtensions: ['json']`） | 加扩展名即可 |
| **PDF 逐页栅格化** | `Printing.raster(bytes, pages, dpi)` → `PdfRaster.toPng()`（printing 5.14.3，**已是现有依赖**） | 已具备，无需新增 |
| PDF **文本提取** | — | **缺**（printing 只能栅格化，不能取文字） |

### 技术选型结论

**推荐 `syncfusion_flutter_pdf`（纯 Dart），不建议 `pdfrx`（PDFium）。**

| 候选 | 影响评估 |
|---|---|
| **`syncfusion_flutter_pdf`** | 纯 Dart：**不碰构建链路**、APK 体积几乎不变、无迁移负担 ← 推荐 |
| `pdfrx` | 底层是 PDFium（Chrome 同款），提取质量最好，但**明确要求 Windows 开启开发者模式才能构建**，而 CI 有 `build-windows` job —— 刚修复完 CI，不宜再引入环境层面的不确定因素；且 2.5+ 自带控件改用 `material_ui` 包，多一层耦合 |
| 纯视觉模型（不引入任何依赖） | 用已有的 `printing` 栅格化 + 视觉链路即可，但有每页一次 API 调用的成本 |

### 未知数（必须先验证，否则可能在错误路线上投入）

中文 PDF 的文本提取质量取决于文件内嵌的 **ToUnicode CMap**。
**字体子集化处理不当**的 PDF 会提取出乱码或私用区字符 —— 这一点无法靠推理确认。

**前置实验（第 0 步）**：拿一页真实教材 PDF，写一个约 20 行的 Dart 脚本只把文字打出来。
三种结果对应三条路：

| 结果 | 后续 |
|---|---|
| 中文干净 | 按本方案实施，零 AI 成本 |
| 部分乱码 | 方案不变，质量检测 + 逐页兜底的权重上调 |
| 整页乱码 | **去掉所有新依赖**，全走视觉模型；改动量反而更小（只需在现有拍照导入前加一段栅格化） |

### 改动清单（范围收敛后）

1. `pubspec.yaml`：+ `syncfusion_flutter_pdf` —— **待第 0 步确认后才加**
2. **新增** `lib/core/pdf_text_extract.dart`（约 120 行）
   - 逐页取文本
   - `scoreChineseQuality(text)`：乱码率 —— U+FFFD 替换符、私用区字符（U+E000–U+F8FF）、
     中文有效字符占比；返回可用性判定
3. `lib/ui/chinese_panel.dart`（约 150 行）
   - **重构（必做，非可选优化）**：把 `_importCorpusFromImage` 里
     「调 AI + 解析结构化结果」那段抽成 `_structureCorpusPage(String imageBase64)`，
     供「拍照导入」与「PDF 导入」共用。**不抽就会把提示词复制成两份**，
     重演本项目「同一份数据两处定义、必有一处漏更新」的坑。
   - 新增 `_importCorpusFromPdf()`：选文件 → 页码范围 → 逐页提取 →
     不合格页回落视觉模型 → 结果预览（可勾选删除）→ 归档
   - 「导入语料(.json)」旁增加「导入教材 PDF」按钮
4. `lib/data/corpus_store.dart`：`origin` 增加取值 `imported-pdf`（**无结构变更**）
5. **新增** `test/pdf_import_test.dart`：质量评分函数的正常 / 乱码 / 空 / 混排用例

### 双通道设计

```
选 PDF → 逐页文本提取 → 质量检测 ─┬─ 合格   → 结构化 {unit,title,text} → 语料库
                                    └─ 不合格 → 栅格化 + 视觉模型（已有链路）→ 语料库
```

### 实施顺序

0. **前置实验**：真实 PDF 一页，确认提取质量（决定是否引入依赖）
1. 抽 `_structureCorpusPage()` + `origin` 加 `imported-pdf` 取值
   —— 无行为变化，可独立提交
2. PDF 提取 + 质量评分 + 单元测试
3. 入口 UI：按钮 + 页码范围选择 + 进度显示 + 可中断
4. 结果预览（可勾选 / 删除识别错误的段落）再入库
5. 真机与 Web 各验证一次；更新 `AGENTS.md` 与 `docs/DATA_MODEL.md`

### 默认值与约束

- **单次导入默认上限 30 页**，弹窗可选区间。教材动辄上百页，
  一次全跑既慢，也可能在部分设备上触发内存问题。
- 走视觉兜底时**逐页调用**，提交前显示预估调用次数（成本透明）。
- **版权**：`Corpus.source` 默认 `''`（未声明·版权自负）已覆盖该场景，
  但 UI 需显式提示「请确认你已获得该教材的合法使用权」。

### 风险

| 风险 | 应对 |
|---|---|
| 大 PDF 内存占用 | 逐页解析，不整本载入 |
| Web 平台兼容 | 纯 Dart 方案无原生依赖，预期可用，但需实测一次 |
| 中文提取乱码 | 质量检测 + 视觉模型兜底（已有链路） |
| API 成本 | 页码区间 + 页数上限 + 预估提示 |
| 识别错字进入课文 | 第 4 步的结果预览：入库前由人工确认 |
